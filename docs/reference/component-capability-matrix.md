# Component capability matrix

This matrix determines whether a capability is configured through Vuetify defaults, wrapped with a
semantic Vela API, composed as a reusable admin pattern, or left as a native primitive. It is a
design input, not a promise that every listed component ships in the first release.

| Area                          | Vuetify foundation                      | Vela capability                        | Strategy                                                                                                                                                       | Mobile contract                                 | MVP |
| ----------------------------- | --------------------------------------- | -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- | --- |
| Primary and secondary actions | `VBtn`                                  | `VaButton`                             | Semantic intent, loading copy, disabled state, responsive width, and reduced-motion behavior                                                                   | Full-width option and accessible touch target   | Yes |
| Text actions                  | `VBtn` text/plain variants              | `VaButton` with `appearance="text"`    | Stable text-action density, icon spacing, destructive intent, focus treatment                                                                                  | Never truncate the only action label            | Yes |
| Icon actions                  | `VBtn`, `VIcon`, `VTooltip`             | `VaIconButton`                         | Required accessible name, tooltip policy, busy state                                                                                                           | Larger touch target than visual icon            | Yes |
| Toggle actions                | `VBtnToggle`                            | Native defaults initially              | Add a wrapper only if validation or semantic selection behavior is needed                                                                                      | Scroll or wrap explicitly                       | No  |
| Avatars                       | `VAvatar`, `VImg`, `VBadge`             | `VaAvatar`                             | Image lifecycle, fallback icon/initial, status, accessible name                                                                                                | Tokenized responsive sizes                      | Yes |
| Avatar collections            | `VAvatar`                               | `VaAvatarGroup`                        | Overlap, overflow count, tooltips, keyboard navigation                                                                                                         | Condense visible members                        | Yes |
| Chips                         | `VChip`, `VChipGroup`                   | `VaChip`                               | Interactive chip semantics and consistent removable state                                                                                                      | Horizontal scroll or wrap                       | Yes |
| Status tags                   | `VChip`                                 | `VaTag`                                | Non-interactive semantic tone and status mapping                                                                                                               | Preserve legibility and contrast                | Yes |
| Badges                        | `VBadge`                                | `VaBadge`                              | Count formatting, caps, accessible announcements                                                                                                               | Avoid clipping in compact headers               | Yes |
| Cards and sheets              | `VCard`, `VSheet`                       | Defaults plus `VaStatCard` patterns    | Keep generic layout native; compose recurring admin cards                                                                                                      | Stack and reorder by priority                   | Yes |
| Text input                    | `VTextField`                            | Form-builder registry                  | Typed schema, help/error/required state, conditions, server error binding                                                                                      | Full width and correct keyboard hints           | Yes |
| Text area                     | `VTextarea`                             | Form-builder registry                  | Typed schema, autosize policy, validation and server errors                                                                                                    | Avoid viewport keyboard overlap                 | Yes |
| Select and autocomplete       | `VSelect`, `VAutocomplete`, `VCombobox` | Form-builder registry                  | Typed options and custom field escape hatch; async option orchestration remains application-owned                                                              | Full-width menu or sheet when needed            | Yes |
| Boolean and choice inputs     | `VCheckbox`, `VRadioGroup`, `VSwitch`   | Defaults plus form-field integration   | Keep native control, unify validation and descriptions                                                                                                         | Accessible labels and touch targets             | Yes |
| Dates and ranges              | Vuetify picker primitives               | Custom field registry entry            | Specialized timezone-aware date and range components remain planned                                                                                            | Application defines modal presentation          | No  |

| Form dialog workflow          | `VDialog`, schema forms                 | `VaFormDialog`, `useFormWorkflow`      | Cancellable record load, echo/payload mapping, validation, submit, retry, and committed dirty state                                                            | Full-screen editor with fixed actions           | Yes |
| Dialogs                       | `VDialog`, `VCard`                      | `VaModal`                              | Header/body/footer, focus, async close guard, busy state                                                                                                       | Full-screen or safe inset mode                  | Yes |
| Confirmation                  | `VDialog`                               | `feedback.confirm`, `VaConfirmHost`    | Queued promise result, destructive intent and configurable copy                                                                                                | Centered, scroll-safe presentation              | Yes |
| Prompt                        | `VDialog`, form fields                  | `feedback.prompt`, `VaPromptHost`      | Queued promise result and synchronous or asynchronous validation                                                                                               | Keyboard-safe content                           | Yes |
| Menus and tooltips            | `VMenu`, `VTooltip`                     | Defaults and targeted composables      | Avoid generic wrappers unless behavior is shared                                                                                                               | Reposition and avoid hover-only access          | Yes |
| Toasts                        | `VSnackbarQueue`                        | `feedback.toast`, `VaFeedbackHost`     | Semantic tone, queueing, duration, timer, close action and screen-reader announcement                                                                          | Safe-area placement                             | Yes |
| Loading                       | Progress primitives                     | `feedback.loading`, `VaLoadingOverlay` | Concurrent global handles plus scoped blocking semantics, delay and minimum visible duration                                                                   | Scoped loading avoids blocking background work  | Yes |
| Skeletons                     | `VSkeletonLoader`                       | `VaSkeleton` presets                   | Stable shapes aligned to actual content                                                                                                                        | Responsive skeleton geometry                    | Yes |
| Empty and error states        | Alerts, icons, buttons                  | `VaStateView` family                   | Empty, filtered-empty, error, offline, 403, 404, dependency unavailable                                                                                        | Compact copy and reachable recovery action      | Yes |
| Data table                    | `VDataTableServer`                      | `VaDataTable`                          | Bounded sizing, identity/media/metric/money/time/status/boolean/progress/trend cells, density inheritance, resize persistence, safe CSV, stable action pinning | Explicit scroll, priority columns, or card mode | Yes |
| Pagination                    | `VPagination`, `VSelect`                | `VaPager`                              | Page-size defaults, range copy, page/offset/cursor modes, bounded direct page jump                                                                             | Compact navigation and sheet/select sizing      | Yes |
| Filters                       | Form/menu primitives                    | `VaFilterBar`, filter schema           | Immediate or submitted modes, chips, URL serialization                                                                                                         | Collapsible mobile filter sheet                 | Yes |
| Data page                     | Table, state views, toolbar             | `VaDataPage`, `useDataPage`            | Request lifecycle, cancellation, refresh, retry, keep-previous-data, URL sync, saved views, viewport fill, fixed tools and pager                               | State-preserving responsive presentation        | Yes |
| File upload                   | `VFileUpload`, progress primitives      | `VaFileUpload`, `useUploadQueue`       | Adapter, queue, remote seeding/deletion guard, max count, progress, cancel, retry, validation, list/gallery presentation                                       | Camera/file source and touch layout             | Yes |
| Image upload                  | File upload, `VImg`, Cropper.js         | `VaImageUpload`, `VaAvatarUpload`      | Preview, ordering, cover/avatar patterns, zoom/rotate/flip crop, output encoding and replaceable preprocessing                                                 | Touch crop controls and safe preview            | Yes |
| App shell                     | `VApp`, `VMain`, layout primitives      | `VaAppShell`                           | Sidebar, compact and topbar layouts, slots, settings and responsive state                                                                                      | Temporary drawer and safe areas                 | Yes |
| Navigation                    | Drawer, list, app bar                   | `NavigationItem`, `VaAppShell`         | Typed section/group/link schema, permission filtering and active state                                                                                         | Temporary drawer policy                         | Yes |
| Access boundaries             | Vue render lifecycle                    | `VelaAccessBoundary`, route guards     | Fail-closed async capabilities, auth initialization, redirect preservation, and host-provided policy context                                                   | Denied/pending slots remain layout-aware        | Yes |
| Tabs and breadcrumbs          | `VTabs`, `VBreadcrumbs`                 | Shell-integrated patterns              | Persistence, overflow, route adapters                                                                                                                          | Scrollable tabs and compact breadcrumbs         | Yes |
| Theme settings                | Theme and display services              | `VaAppearanceSettings`                 | Tabbed settings: mode, color, skin, layout, canvas, header, spacing, density, radius, opacity, text scale, contrast, motion                                    | Scroll-safe centered modal                      | Yes |
| Virtual lists                 | `VVirtualScroll`                        | Native or data integration             | Introduce only after measured need                                                                                                                             | Preserve keyboard navigation                    | No  |
| Timeline, carousel, stepper   | Native primitives                       | Native defaults                        | No generic wrapper without a repeated admin contract                                                                                                           | Follow native responsive behavior               | No  |

## Wrapper acceptance checklist

A proposed public component must answer all of these questions:

1. What stable behavior does it add beyond global defaults?
2. Which Vuetify capabilities remain accessible through props, attributes, events, or slots?
3. What are its loading, empty, error, disabled, and destructive states where applicable?
4. What is its keyboard and screen-reader contract?
5. What changes at each responsive breakpoint?
6. Which tokens does it consume, and does it introduce an unregistered visual literal?
7. How is the behavior demonstrated, unit-tested, browser-tested, and documented?
